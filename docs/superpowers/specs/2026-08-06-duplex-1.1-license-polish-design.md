# Duplex 1.1 — License Gate, Window Identity, Search

**Date:** 2026-08-06
**Status:** Approved (design + gap review approved in conversation)
**Baseline:** Duplex 1.0 (commit 10970ea), 46 tests green

## Goal

Prepare Duplex for paid distribution ($5, Lemon Squeezy) outside the Mac App
Store: a one-instance-free license gate, a window that carries the app's
identity, and a search field for the instance list.

## Decisions (user-confirmed)

- Payments: **Lemon Squeezy** (merchant of record; public license API).
- Free tier: **one instance free forever** — one wrapper total across all
  target apps, counted by `InstanceStore.scan` at create time.
- List UX: **scroll + toolbar search**, no pagination.

## 1. License gate

### Gate rule (pure, unit-tested, in DuplexKit)

```
canCreate(existingCount: Int, isRegeneration: Bool, licensed: Bool) -> Bool
```

- `isRegeneration == true` (Edit flow, `existingSlug != nil`) → **always
  allowed**. Editing the free instance is free.
- Otherwise allowed when `existingCount < 1 || licensed`.
- Launch, Edit, Delete, Reveal, and link routing are never gated.
- **Wrappers never check the license.** The launcher stays license-blind;
  existing clones work forever regardless of payment state.
- Grandfathering: pre-1.1 users with N instances keep full use of all N;
  only net-new creation is gated.

### LicenseManager (DuplexKit)

State machine persisted in `UserDefaults` (`free` / `licensed(key,
activationID, lastValidated)`):

- **Activate:** POST Lemon Squeezy `licenses/activate` with the key and an
  instance name (host name). Success stores key + activation ID. No API
  secrets ship in the app (LS license endpoints are public, per-key).
- **Re-validate:** on launch, in the background, at most weekly: POST
  `licenses/validate`. Explicit `valid: false` (refund/disabled) → downgrade
  to free with a clear message. **Network failure never downgrades** —
  last-known-good wins indefinitely.
- **Deactivate:** POST `licenses/deactivate`, clear local state ("move to
  another Mac" path).
- Activation-limit failure surfaces LS's message plus guidance to deactivate
  another Mac. Default limit configured store-side (3 suggested).
- All HTTP behind a `LicenseClient` protocol; tests use a stub. The state
  machine (activate success/failure, revoked, offline, deactivate) is
  unit-tested without network.
- Accepted non-goals: `UserDefaults` is hand-editable and offline-forever
  keeps a revoked key working — this is casual-sharing deterrence for a $5
  utility, not DRM.

### GUI

- **Buy/activate sheet** (shown when the gate blocks creation, and via menu):
  one-line pitch, key field, Activate button, error area, "Buy for $5" link
  opening `DuplexConfig.checkoutURL` (constant; placeholder until the user's
  LS store exists), and a plain-language privacy note: only the key is sent,
  and only when activating/validating.
- **License… menu item** (app menu) opening the same sheet; when licensed it
  shows status (key suffix, activated date) and a **Deactivate this Mac**
  button.
- **Footer status line** in the main window: "Free · 1 of 1 free instances
  used · Enter license…" / "Licensed". Quiet; never modal on its own.

## 2. Window identity

- Empty state: large app icon (`NSApp.applicationIconImage`), headline
  ("Run a second copy of any Electron app"), one supporting line, prominent
  **New Instance…** button.
- Populated state: slim header with small app icon + "Duplex"; footer license
  line as above.

## 3. Search

- Toolbar search field (`.searchable` on the List); filters rows live on
  instance name OR target app name; case- and diacritic-insensitive
  (`localizedStandardContains` semantics).
- Empty-result state: "No instances match" placeholder.

## Versioning & docs

- `CFBundleShortVersionString` → 1.1 in `scripts/build-app.sh`.
- README: pricing/licensing section deferred to the release phase (Phase A
  notarization + LS store setup are user-side prerequisites and out of scope
  for 1.1 code).

## Non-goals (1.1)

No trial clock, no deep-link key redemption, no receipt validation, no seat
management beyond activate/deactivate, no analytics, no pagination.

## Testing

- Unit: gate rule truth table (incl. regeneration exemption); LicenseManager
  state machine over stubbed client (activate ok/limit/invalid; validate ok/
  revoked/offline; deactivate); search filter predicate.
- Manual: sheet flows (activate, error, deactivate), footer states, empty
  state, search UX.
- Suite baseline 46 must stay green.
